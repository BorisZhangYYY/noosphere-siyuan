# 开发环境与架构设计

知流是运行于思源笔记中的 TypeScript 插件。网页抓取、模型审阅、正文编辑与思源写入各自独立，通过文章和草稿数据连接。

## 开发环境

- Node.js 22 与 npm，使用 `package-lock.json` 固定依赖。
- 思源笔记 3.8.6 或更新版本，用于运行插件和验证界面交互。
- TypeScript、Vite、Vitest；思源 SDK 由运行时提供，构建时作为外部模块。
- 真实抓取需要 Firecrawl API Key；真实 AI 审阅需要配置文字模型和可选的识图模型。自动测试使用模拟接口。

在项目根目录运行：

```sh
npm ci
npm test
npm run build
npm run package
```

`npm run build` 先进行类型检查，再生成 `dist/`。`npm run package` 在构建后生成 `package.zip`，其中直接包含插件文件，没有额外的顶层文件夹。

仓库中的 `.docs/`、`.project/` 在安装包中分别映射为 `docs/`、`project/`，Markdown 链接同时转换。安装包不包含点开头的路径，确保文档与截图参与思源同步。

本地调试时，将 `dist/` 内容复制到测试工作空间的 `data/plugins/noosphere-siyuan/`，再启用插件或重新加载思源界面。服务配置在知流“设置”中填写。

## 项目结构

| 路径 | 职责 |
| --- | --- |
| `src/index.ts` | 插件生命周期、顶部入口、工作台操作与流程调度 |
| `src/ui.ts`、`src/style.css` | 工作台与配置页的界面结构和样式 |
| `src/crawler/` | Firecrawl 请求与抓取结果解析 |
| `src/article/` | 来源与时间、正文组装、草稿、历史、预览与原生编辑 |
| `src/review/` | 模型协议、供应商配置、提示词、流式正文与图片审阅 |
| `src/images/` | 图片地址归一化、资源下载和引用替换 |
| `src/siyuan/` | 思源请求封装、流式连接、文档写入与插件数据清理 |
| `src/types.ts` | 文章、设置与审阅视角等共享数据类型 |
| `tests/` | 抓取、审阅、历史、编辑、图片与写入的回归测试 |
| `.docs/` | 英文介绍与工作台截图 |
| `.project/` | 开发环境与架构说明 |
| `scripts/finish-build.mjs` | 将插件元数据、说明、截图和许可证复制到安装包 |

## 内容处理流程

1. 用户输入 URL，由思源请求代理调用 Firecrawl v2 `/scrape`，取得 Markdown 和可用元数据，并记录抓取时间。
2. 抓取成功后更新当前文章并加入历史；抓取失败时保留已有正文。
3. 用户可以直接编辑原文，也可以选择视角和语言进行 AI 审阅。人工编辑后的正文会作为后续审阅输入；未编辑的文章使用完整抓取原文。
4. 文字审阅完成后，可用文章摘要和配图进行独立图片审阅。移除建议由用户调整；模型识别失败时保留图片。
5. 手动模式指定目标文档并点击保存；自动模式在整次审阅成功后读取锚点子树的分类和介绍，选择已有分类并自动保存。图片本地化后再写入正文、来源与引用。
6. 手动模式向已有文档追加；自动模式按来源身份查重、更新原文章并保护不同来源的同名笔记。目录块独立刷新，失败保留重试目标；取消或审阅失败不落库。

## 抓取与模型接口

网页抓取统一使用 Firecrawl API，本版没有 Crawl4AI 运行依赖，也没有按网站分别选择抓取器。微信公众号和知乎的来源名称转换、微信图片地址归一化属于抓取结果整理。

模型设置按供应商保存，协议处理集中在 `src/review/`，支持 OpenAI Chat Completions、OpenAI Responses、Anthropic Messages 和 Google Gemini。供应商预设与请求协议分离，文字模型和图片模型可以分别配置。

请求通过 `src/siyuan/api.ts` 封装；桌面端与浏览器前端分别使用适合其环境的流式连接。正文逐步显示、跟随滚动和图片审阅进度分别管理，正文显示完成即结束跟随。

## 编辑与数据保存

正文使用思源 Protyle 轻量编辑器，编辑期间保留 Markdown、原生 Markdown 和块 DOM。弹窗确认、关闭与历史切换会保留文章修改，不创建额外的思源草稿文档。

来源信息与正文分开维护，预览和正式写入时按字段组装。正式导入会生成独立的块标识，并调整内部引用，保留原生格式。

插件通过思源提供的存储接口保存 `settings.json`、`capture-draft.json` 和 `capture-history.json`；前端恢复缓存按工作空间区分。设置、当前文章和历史分别维护，关闭、禁用或升级保留数据。启用状态下卸载插件时清理自身存储和当前前端的恢复缓存，已导入文档与资源继续保留。

## 内核集成验证

`tests/siyuan.integration.test.ts` 默认跳过；需要独立的本机思源测试内核。设置 `SIYUAN_TEST_URL`（HTTPS 地址）和 `SIYUAN_TEST_TOKEN`（该临时工作空间的 API Token）后，运行 `npx vitest run tests/siyuan.integration.test.ts`。测试会创建并删除带“知流集成测试”前缀的临时笔记本，不应指向日常工作空间。自签名证书处理仅存在于集成测试中。

测试覆盖真实分类 SQL、正文介绍、文档创建与来源查重、同名保护及目录重写。读取 SQL 前同步内核写入队列，避免刚创建的来源标记或目录块尚未索引时重复创建。

## 验证与发布

修改后运行与行为相关的测试；发布前运行 `npm test` 和 `npm run package`，检查元数据版本、安装包文件和 README 图片引用。界面交互使用独立测试工作空间验证。

仓库检查流程负责必需文档和敏感文件检查；插件构建流程负责测试、构建与安装包校验。正式版本需要保持 `package.json`、`plugin.json` 和 `v版本号` 标签一致，发布资产名为 `package.zip`。

提交与反馈规范见根目录的 [CONTRIBUTING.md](../CONTRIBUTING.md)。
