# 开发环境与架构设计

知流是运行于思源笔记中的 TypeScript 插件。网页抓取、模型审阅、正文编辑与思源写入各自独立，通过文章和草稿数据连接。

## 开发环境

- Node.js 22 与 npm，使用 `package-lock.json` 固定依赖。
- 思源笔记 3.8.6 或更新版本，用于运行插件和验证界面交互。
- TypeScript、Vite、Vitest；思源 SDK 由运行时提供，构建时作为外部模块。
- 真实抓取需要 Firecrawl API Key；真实 AI 审阅需要配置文字模型和可选的识图模型。自动测试使用模拟接口。

在项目根目录运行：

```sh
npm ci
npm test
npm run build
npm run package
```

`npm run build` 先进行类型检查，再生成 `dist/`。`npm run package` 在构建后生成 `package.zip`，其中直接包含插件文件，没有额外的顶层文件夹。

仓库中的 `.docs/`、`.project/` 在安装包中分别映射为 `docs/`、`project/`，Markdown 链接同时转换。安装包不包含点开头的路径，确保文档与截图参与思源同步。

本地调试时，将 `dist/` 内容复制到测试工作空间的 `data/plugins/noosphere-siyuan/`，再启用插件或重新加载思源界面。服务配置在知流“设置”中填写。

## 项目结构

| 路径 | 职责 |
| --- | --- |
| `src/index.ts` | 插件生命周期、顶部入口、工作台操作与流程调度 |
| `src/ui.ts`、`src/style.css` | 工作台与配置页的界面结构和样式 |
| `src/crawler/` | Firecrawl 请求、通用抓取策略与抓取结果解析 |
| `src/crawler/platforms/` | 按平台独立维护链接规整、来源与正文整理及结果校验 |
| `src/article/` | 来源与时间、正文组装、草稿、历史、预览与原生编辑 |
| `src/review/` | 模型协议、供应商配置、提示词、流式正文与图片审阅 |
| `src/images/` | 图片地址归一化、资源下载和引用替换 |
| `src/siyuan/` | 思源请求封装、流式连接、文档写入与插件数据清理 |
| `src/types.ts` | 文章、设置与审阅视角等共享数据类型 |
| `tests/` | 抓取、审阅、历史、编辑、图片与写入的回归测试 |
| `.docs/` | 英文介绍与工作台截图 |
| `.project/` | 开发环境与架构说明 |
| `scripts/finish-build.mjs` | 将插件元数据、说明、截图和许可证复制到安装包 |

## 内容处理流程

1. 用户输入 URL，按需规整分享链接，再由思源请求代理调用 Firecrawl v2 `/scrape`；所有平台统一在正文抽取前等待 5 秒。返回后先验证平台响应，再整理 Markdown 与可用元数据，并记录抓取时间。
2. 抓取成功后更新当前文章并加入历史；抓取失败时保留已有正文。
3. 用户可以直接编辑原文，也可以选择视角和语言进行 AI 审阅。人工编辑后的正文会作为后续审阅输入；未编辑的文章使用完整抓取原文。
4. 文字审阅完成后，可用文章摘要和配图进行独立图片审阅。移除建议由用户调整；模型识别失败时保留图片。
5. 手动模式指定目标文档并点击保存；自动模式在整次审阅成功后读取锚点子树的分类和介绍，选择已有分类并自动保存。图片本地化后再写入正文、来源与引用。
6. 手动模式向已有文档追加；自动模式按来源身份查重、更新原文章并保护不同来源的同名笔记。目录块独立刷新，失败保留重试目标；取消或审阅失败不落库。

## 抓取与模型接口

网页抓取统一使用 Firecrawl API、Markdown 输出与正文抽取，所有平台均采用 `waitFor: 5000`。等待参数只在通用策略中设置，不保留按平台覆盖、叠加或省略等待的配置。本版没有 Crawl4AI 运行依赖，也没有按网站分别选择抓取器。

抓取代码按以下职责维护：

- `src/crawler/firecrawl.ts` 负责 URL 校验、思源代理请求和响应解析，不写平台分支。
- `src/crawler/policy.ts` 负责通用抓取参数、链接规整和结果处理入口，未知平台自动沿用默认策略。
- `src/crawler/platforms/types.ts` 定义当前 Firecrawl 路径可用的数据与平台约定：网址匹配、来源名称、链接规整、结果校验与整理。
- `src/crawler/platforms/index.ts` 只负责登记和查找平台规则；微信公众号、知乎、小黑盒各有一个独立文件。
- `src/article/source.ts` 复用同一平台登记表展示名称；界面、历史与思源写入不重复处理平台规则。

从 [Noosphere 原版](https://github.com/BorisZhangYYY/Noosphere/tree/3f757e465b8a06d813d117248a9efc016ce698d5/src/platforms) 迁入的规则仅使用当前插件可获得的 Markdown、元数据、原站状态码与原始分享链接：

- 微信公众号只补全缺失的作者与日期，保留 Firecrawl 已返回的字段。清理明确的阅读器与尾部界面文案，保留代码和引用；封面横幅只有在同一图片确实重复且符合原版短标题模式时才移除，至少保留一份。微信图片身份归一化继续复用图片模块。
- 小黑盒兼容 API 分享入口和旧版 `/bbs/post_share`，仅将有效且唯一的 `link_id` 转为正文地址。清理标题后缀，缺失标题依次从正文一级标题、原分享 URL 的 `redirect_data.link.title` 补全。分享描述不替代文章正文。识别到页面开头的标题与作者卡片后，补全缺失作者和显式日期，清理关联游戏入口、评论与推荐外壳；保留文章配图、投票及代码引用中的同名文案，不推测日期缺少的年份。
- 知乎拒绝原站状态为 401、403、429 的结果；正文去掉图片、链接地址和空白后不足 800 字且含原版访问墙标记时也拒绝。长文章引用相同提示时保留。校验失败会在创建历史或后续审阅前抛出错误。

原版依赖 Crawl4AI 的浏览器脚本、正文选择器、HTML 解析和双抓取器回退未迁入；不向 Firecrawl 发送这些不兼容参数，也不额外发起付费重试。原版的统一 100 字门槛不适用于插件的任意网址剪藏，插件继续接受非空短文；平台处理或占位图清理后为空的结果仍报告失败。

新增平台时先验证通用策略。确有例外才添加 `platforms/<平台>.ts` 并登记，补充实际行为的回归测试；只填写已有特殊规则，不为空白平台创建文件或复制抓取流程。

模型设置按供应商保存，协议处理集中在 `src/review/`，支持 OpenAI Chat Completions、OpenAI Responses、Anthropic Messages 和 Google Gemini。供应商预设与请求协议分离，文字模型和图片模型可以分别配置。

文字审阅前由 `src/review/links.ts` 将输入中的图片和链接目标替换为本次请求的引用编号；真实地址仅留在插件内存映射中。流式预览与最终结果使用同一映射还原，编号损坏或未知链接在接受正文和图片审阅前报错，由原有流程保留原稿；遗漏原图仍按原文位置补回。标题层级仅通过文章格式提示词约束：模板定义父章节，原文章节依其层级嵌套，内置和自定义视角共用，不根据固定章节名称事后改写 Markdown。

请求通过 `src/siyuan/api.ts` 封装；桌面端与浏览器前端分别使用适合其环境的流式连接。正文逐步显示、跟随滚动和图片审阅进度分别管理，正文显示完成即结束跟随。

## 编辑与数据保存

正文使用思源 Protyle 轻量编辑器，编辑期间保留 Markdown、原生 Markdown 和块 DOM。弹窗确认、关闭与历史切换会保留文章修改，不创建额外的思源草稿文档。

来源信息与正文分开维护，预览和正式写入时按字段组装。正式导入会生成独立的块标识，并调整内部引用，保留原生格式。

插件通过思源提供的存储接口保存 `settings.json`、`capture-draft.json` 和 `capture-history.json`；前端恢复缓存按工作空间区分。设置、当前文章和历史分别维护，关闭、禁用或升级保留数据。启用状态下卸载插件时清理自身存储和当前前端的恢复缓存，已导入文档与资源继续保留。

## 内核集成验证

`tests/siyuan.integration.test.ts` 默认跳过；需要独立的本机思源测试内核，并开启“顶层笔记本文档”以覆盖笔记本根的目录维护。设置 `SIYUAN_TEST_URL`（HTTPS 地址）和 `SIYUAN_TEST_TOKEN`（该临时工作空间的 API Token）后，运行 `npx vitest run tests/siyuan.integration.test.ts`。测试会创建并删除带“知流集成测试”前缀的临时笔记本，不应指向日常工作空间。自签名证书处理仅存在于集成测试中。

测试覆盖真实分类 SQL、正文介绍、文档创建与来源查重、同名保护及目录重写。读取 SQL 前同步内核写入队列，避免刚创建的来源标记或目录块尚未索引时重复创建。

## 验证与发布

修改后运行与行为相关的测试；发布前运行 `npm test` 和 `npm run package`，检查元数据版本、安装包文件和 README 图片引用。界面交互使用独立测试工作空间验证。

仓库检查流程负责必需文档和敏感文件检查；插件构建流程负责测试、构建与安装包校验。正式版本需要保持 `package.json`、`plugin.json` 和 `v版本号` 标签一致，发布资产名为 `package.zip`。

提交与反馈规范见根目录的 [CONTRIBUTING.md](../CONTRIBUTING.md)。
