# 安装与使用

## 环境

- 思源笔记 3.7.0 或更新版本（桌面版、Docker 或桌面浏览器前端）。
- 可访问 Firecrawl API 的网络和 Firecrawl API Key。
- 使用“原文”时无需 AI。使用 AI 审阅时，在知流选择模型供应商并配置 API Key 与模型；支持常见供应商及自定义接口。

## 本地安装

从 [v0.1.3 GitHub Release](https://github.com/BorisZhangYYY/noosphere-siyuan/releases/tag/v0.1.3) 下载 `noosphere-siyuan-v0.1.3.zip`，解压到思源工作空间的 `data/plugins/noosphere-siyuan/`。本版仍为 MVP 预览版，暂不在思源集市提供安装；也可按下述方法本地打包。

也可在项目目录执行 `npm install` 和 `npm run package`，再将生成的 `package.zip` 解压到同一目录。启用插件后，按 `⌥⇧⌘N` 打开知流；也可在命令面板搜索“知流：采集网页文章”，或点击顶部工具栏的地球图标。图标只有一个，可以拖到顶部左侧或右侧；右键菜单也能调整位置。如果顶部按钮被隐藏，可在工具栏的显隐菜单中打开。

开发时可运行 `npm run build`，然后把 `dist/` 内容放入上述插件目录并重新加载思源界面。

## 采集文章

1. 首次打开会进入配置页。填写 Firecrawl API Key；如需 AI 审阅，再选择供应商并配置模型。然后点击“保存并进入工作台”。
2. 在工作台顶部输入文章 URL 并抓取。正文以思源 Markdown 阅读排版显示图片、标题和表格。左侧正文与右侧信息栏独立滚动；右侧依次显示来源、AI 审阅和素材，保存位置固定在右侧底部。工作台只提供阅读，导入思源后可使用拖动、`/` 菜单等完整编辑功能。
3. 来源区默认展示作者与发布时间，点击“编辑”后可补充或更正，点击“确定”才保存并更新文章来源。可选：选择“原文”可直接检查抓取正文并保存，不调用 AI；选择“基于原文”或“小白视角”时可点击“AI 审阅”并检查结果。等待模型时进度条显示动态等待状态；生成正文后根据文章长度、实际生成时长和到达速度动态调整显示速度，以短缓冲平滑展示阅读预览和实际显示的字数，可点击“跟随输出”暂停自动滚动。模型未提供完整输出长度，正文阶段不显示推算百分比；图片阶段按实际已处理数量更新，全文显示与图片处理都结束后显示 100%，并标记审阅完成。显示持续跟随生成速度，不积压固定慢速队列；最后一帧文字与完成状态同步。失败时停止，具体原因统一显示在思源消息提示中。
4. 填写目标思源文档 ID，或点击“使用当前文档”，再点击“保存文章”。目标必须是**文档**。
5. 保存成功后点击“打开文档”跳转查看。插件把文章标题、来源与正文追加到目标文档末尾，不覆盖原文档内容。文章中的 Markdown 图片会自动尝试保存到思源资源目录，无须另选开关。

正文顶部只显示“只读”，不显示草稿保存或恢复提示。工作台仍自动保留当前草稿，关闭窗口或重启插件后会恢复正文、审阅结果、图片取舍、文章链接和保存位置。检查文章或调整图片后可以直接退出，无须先点击“保存文章”；“保存文章”用于正式写入思源文档。输入另一个链接时当前正文仍会保留，只有新文章抓取成功后才会替换草稿，此前文章继续保留在历史记录中。

流式预览根据实际数据到达间隔安排吐字，分批返回时在两批之间连续显示，高速生成时每帧可显示多字，不使用固定字速，也不在结束时集中补齐正文。已排好的段落、文字和图片节点持续复用；跟随输出会平滑追赶正文与图片高度，避免突然跳到最底部。校验后补回图片或调整空白时，已经显示的文字不再退回后重新吐出。供应商长时间停止返回新内容时仍会等待，不生成虚假的预览文字。正文已经输出、模型仍在生成内部摘要或确认结果时，显示“正文已输出，等待模型确认”。模型校验后的处理稿自动保留，页面等待最后一字显示后才标记完成。未校验的流式内容不会保存为有效审阅稿。连接中断、输出截断或结果格式无效时恢复之前的正文，避免把未完成内容写入思源。使用不支持流式代理的旧思源内核时自动等待完整响应；供应商忽略流式参数时同样展示完整结果，不模拟逐字输出。

桌面端通过思源提供的原生连接读取流式响应，避免代理压缩将短文积压到最后才显示。本机 HTTPS 连接使用当前工作空间的 CA 验证思源证书，不关闭证书校验；远程 HTTPS 连接使用默认信任链。浏览器前端继续使用同源代理，其缓冲行为取决于思源内核及反向代理配置。

审阅过程中可点击“取消审阅”，在思源警告弹窗中确认后停止当前正文与图片请求；关闭警告或取消确认会继续审阅。确认停止后，并恢复本次审阅开始前的正文、来源信息和图片取舍，历史记录同步恢复。已经开始流式输出或正在审阅图片时，取消仍会恢复开始前的内容。审阅完成后保留结果，“取消审阅”按钮消失，完成后的审阅不提供撤销或版本回退。

成功写入后仍可阅读文章和打开已保存的文档；选择其他保存位置后可重新保存。图片下载失败时，原图片链接会留在正文里，完成信息会给出失败数量。预览会按文章来源解析相对图片地址，并显示思源中的本地图片；来源网站不可访问时显示图片说明。

正文 AI 审阅单次最多等待 60 分钟，模型服务或中间代理仍可能提前超时。Kimi Code 会按文章长度增加输出预算，最多请求 32768 tokens；服务实际支持的上限以模型为准。超时、输出截断或响应格式错误会分别提示，失败时保留当前草稿。可稍后重试或换用支持长文的模型；具体错误文字统一显示在思源消息提示中。

## 历史记录

点击工作台顶部的“历史记录”查看文章，列表按抓取时间从新到旧排列，可按标题、链接或作者搜索。同一链接再次成功抓取会保留独立记录，抓取失败不增加记录。升级前保留的单篇草稿会自动加入历史，无法恢复此前已被替换的草稿。

- **查看文章**：打开原有处理稿，恢复来源信息、审阅视角、图片取舍和保存位置。
- **删除**：确认后从历史移除；若为当前文章，同时清空其工作台草稿。已导入思源的文章和图片继续保留。

历史记录统一通过“查看文章”打开文章页。需要重新审阅时，在文章页选择审阅视角并点击“AI 审阅”；需要导入时，在文章页确认保存位置并点击“保存文章”。打开历史文章不会自动开始审阅或导入。

切换历史文章会保留当前文章的修改；关闭、禁用或升级插件不会清空历史。

## 获取 Firecrawl API Key

1. 打开 [Firecrawl API Keys 页面](https://www.firecrawl.dev/app/api-keys)。未登录时会先进入登录或注册页面。
2. 登录后进入 API Keys，创建一枚供知流使用的 Key，并复制以 `fc-` 开头的值。
3. 回到知流首次配置页，粘贴到 **Firecrawl API Key**，点击“保存并进入工作台”。
4. 粘贴公开网页链接，点击“抓取文章”验证配置。API Key 无效、额度不足或网页无法访问时，思源会显示服务返回的错误提示。

Firecrawl 的服务说明与接口文档见[官方文档](https://docs.firecrawl.dev/)。Firecrawl 的套餐与额度可能调整，请以其页面显示为准。API Key 相当于密码，请勿放入公开文档或截图。


## 配置 AI 审阅模型

知流直接连接模型供应商，不调用思源内置编辑模型。按供应商分别记住 API Key、模型、接口和识图能力；切换供应商不会覆盖其他供应商的设置。预置 Kimi API、Kimi Code、火山引擎、MiniMax、智谱 AI、OpenAI、Anthropic 和 Google Gemini；“自定义”支持兼容接口。

工作台的“输出语言”和设置页的“文章输出语言”同步，可选择“跟随思源界面”“保持原文语言”“简体中文”或“英文”。跟随模式每次按思源当前的界面语言选择中文或英文；保持原文模式保留原文主要语言。语言要求适用于文章标题、正文、章节名称与 AI 补充，代码、链接和来源证据保留原样。语言选择随文章保留，打开历史文章后会恢复原来的选择；选择原文视角时不调用 AI，也不翻译文章。

审阅分三段：知流内部固定的通用去噪、元数据和 JSON 接口约束；用户选择的视角提示词与自然语言文章格式要求；文字审阅结束后、使用内部摘要建立新上下文进行图片审阅。内置“基于原文”和“小白视角”只读，原文模式不调用模型。固定系统约束不在界面展示或编辑。

在“设置”的“审阅视角与文章格式”中点击“新增视角”，会复制当前视角的提示词，并默认填入不显示摘要的要点式文章格式；可编辑名称、视角提示词和文章格式，保存后在工作台选择使用。“视角提示词”决定怎样理解与保留原文；“文章格式要求”可直接用带分隔线与 Markdown 章节的文字版式描述希望生成的结构，无需记忆变量。内置格式保留 Noosphere 的“AI 摘要 / 正文”与“快速理解 / 阅读前准备 / 正文与讲解”章节。内置视角的两项内容可查看，但不能直接修改。旧版已保存的变量模板会转换为可编辑的文字说明。

修改设置或新增视角后，请点击“保存并进入工作台”。若直接返回工作台，知流会提示确认；确认后会放弃本次未保存的修改。

标题、来源、作者、发布时间由知流组装，不用在文章格式里写占位符。抓取不到作者或发布时间时，AI 可提出候选值及逐字引用的原文证据；知流核对证据后填充。已经抓到或手动填写的非空值不会被 AI 覆盖。模型另生成一段仅供图片判断的内部摘要；要求文章“不显示摘要”时，这段内容不会加入正文。

配置模型：

1. 选择供应商。Kimi API 与 Kimi Code 使用不同的 Key 和地址；Kimi Code 预填 `kimi-for-coding`，其余模型 ID 以供应商实际提供的为准。
2. 填写该供应商的 API Key。入口旁可点“获取 API Key”。点击“获取模型”选择服务返回的模型；若服务不支持列表接口，可手动填写模型 ID。
3. 官方预设已填好常用 API 地址与协议。只有代理网关或特殊接口才展开“接口设置”修改。支持 OpenAI Chat Completions、OpenAI Responses、Anthropic Messages 和 Google Gemini。
4. “原文”不调用模型；其他审阅视角使用当前选中的供应商。

### 图片审阅

默认关闭。请先在某个供应商下勾选“这个模型支持识图”，再从“图片审阅模型”中选择它。图片模型与文字模型可以属于不同供应商。请根据供应商说明确认具体模型是否支持图片；模型列表只提供名称，无法可靠判断识图能力。

知流先审阅文字，并让模型生成一段不写入文章的内部摘要。文字模型漏掉的原有图片会补回，再让图片模型结合摘要逐张判断。疑似广告、二维码或无关装饰图会显示为“建议移除”，正文预览先隐藏；可在右侧素材缩略图取消移除勾选，或点击图片打开详情并恢复。详情会展示图片判断与原始图片来源。最终保存以当前正文预览为准。判断不明确、下载失败或模型报错时保留图片。素材区显示已审阅、待审阅与失败数量，失败原因可在图片详情查看。单篇图片数量没有上限，点击“AI 审阅”后自动审阅完整正文与所有图片，相同地址的多个引用共享本次识别结果。插件不按图片数量或单张大小跳过图片。导入思源时也会逐张尝试处理整篇文章的图片，不按数量跳过。

正文、素材缩略图和大图共用图片地址解析。本地图片从当前思源的 `/assets/` 读取；旧草稿的错误资源地址会自动修正。图片本地化后，素材预览读取本地资源并保留原图片来源。

抓取结果中误写成图片的文章页链接会自动过滤，历史文章同样适用。图片失败提示区分“图片下载失败”和“图片模型请求失败”，显示 HTTP 状态及简短原因，不展示错误网页或 Base64 数据；真实图片下载受限时继续保留原图。图片进度实时显示并更新恢复缓存，每五秒合并保存到思源；关闭窗口、取消及审阅完成时立即保存，重复快照不重复写入，以减少长文审阅产生的日志。

工作台统一使用“AI 审阅”入口：每次从完整抓取原文开始审阅，再自动处理全部图片，整次流程结束后才显示完成。处理中自动保留校验后的正文和已返回的图片判断。在思源持续运行的情况下，关闭知流窗口只暂停画面，正文与图片审阅继续在后台进行；重新打开可查看同一次审阅的实时进度。后台完成后通过思源消息通知，结果保留在文章和历史记录里。退出思源或禁用插件会停止当前请求，保留已有有效结果。

OpenAI 的 [Responses API](https://developers.openai.com/api/reference/resources/responses/methods/create) 与 [模型列表](https://developers.openai.com/api/reference/resources/models/methods/list)、Anthropic 的 [Messages API](https://platform.claude.com/docs/en/api/messages/create) 与 [模型列表](https://platform.claude.com/docs/en/api/models/list)、Google 的 [Gemini API](https://ai.google.dev/api) 与 [模型列表](https://ai.google.dev/api/models) 可用于核对端点和模型 ID。

## 配置与数据

### 卸载与清理

完整清理请在插件启用时通过思源的插件管理卸载知流。卸载钩子会清除当前工作空间的 `data/storage/petal/noosphere-siyuan/` 目录，包括设置、API Key、草稿、文章历史、审阅结果、图片取舍和保存位置，并删除当前前端中该工作空间的草稿与历史恢复缓存。已开始的插件文件写入结束后才删除目录，已卸载的实例不再接受新的保存。

普通关闭窗口、禁用或升级保留这些数据。已经写入思源文档的文章与资源属于笔记内容，继续保留。

思源对已禁用的插件或直接删除插件目录的操作不会执行插件清理钩子；采用这两种方式时，需要额外清理上述数据目录。其他浏览器或未运行的前端中的恢复缓存也不在当前前端的清理范围内。

### 设置和草稿

点击知流窗口标题栏右侧的“设置”进入服务配置，配置保存在当前思源工作空间的插件数据中。API Key 默认以固定数量的圆点隐藏，可点击输入框内的眼睛图标查看或再次隐藏。插件存储不是加密保险箱；只在自己信任的工作空间中保存密钥。文章内容会发送至 Firecrawl；启用 AI 审阅时，正文还会发送至所配置的模型服务。

文章抓取使用 Firecrawl API。Crawl4AI 是 Python SDK，不能直接运行在思源前端插件的 JavaScript 环境中；若要使用它，需要另行部署服务，故不作为本版必选依赖。
